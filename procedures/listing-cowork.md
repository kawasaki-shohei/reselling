# 出品手順 (フリマサイト) — Cowork 版

本手順書は **Claude Cowork + Claude in Chrome** で実行することを前提に書かれている。Claude Code + Playwright 前提の手順書は別ファイル [`listing.md`](./listing.md) にある。両者は「どのサイトの・どの項目に・どの値を入れるか」は共通で、ブラウザの操作手段だけが異なる。

対応販路は **メルカリ**、**ヤフーフリマ**、**ヤフオク (フリマ形式)**。共通章 (出品方法・前提条件・制約事項・CSV 仕様・状態管理) と販路別章 (フォーム入力フロー・トラブル対応) を読み分けること。

## やりたいこと

本ドキュメントは [`overview.md`](../overview.md) の **出品・販売・SEO対策** の手順書である。

商品リサーチから写真撮影・商品説明ページ作成まで完了した中国輸入商品を、メルカリ・ヤフーフリマ・ヤフオクの出品フォームに登録するまでの作業を扱う。出品後の値下げ・問い合わせ対応・梱包・発送はそれぞれ別工程で扱う。

---

## 採用する出品方法

**Claude Cowork が、Claude in Chrome 拡張機能を通じてユーザーの普段使っている Chrome を操作し、各販路の出品フォームを 1 件ずつ埋める**方式を採用する。

具体的には:

1. ユーザーが普段使っている Chrome に Claude in Chrome 拡張をインストール済みにしておく
2. ユーザーが Chrome で各販路 (メルカリ・Yahoo! JAPAN・ラクマ等) にログインしておく。**一度ログインすればブラウザにセッションが残るので、次回以降は再ログイン不要**
3. Cowork が本手順書を読み、Claude in Chrome を通じて画面を見ながらフォームを埋める
4. 1 件出品するたびに画面を確認し、ユーザーが結果を確認できる

Claude in Chrome は**画面を見てボタンをクリック・文字を入力する**方式 (人間と同じ操作) で動く。事前にスクリプトを書く必要はなく、本手順書の自然言語の指示どおりに操作する。

完全自動の無人実行スクリプトは採用しない。理由は次節。

## なぜ完全自動スクリプトでないのか

### 規約上の理由

#### メルカリ

メルカリ運営は 2017 年に**「自動出品ツール (メルカリに自動で出品を行うソフトウェア等) の利用を禁止」**することを公式発表している ([運営プレスリリース 2017-06-16](https://about.mercari.com/press/news/articles/20170616_anti-fraud/))。さらに [メルカリガイド「その他、不適切と判断される行為」](https://help.jp.mercari.com/guide/articles/900/) には「弊社が提供するインターフェイスとは別の手法を用いてサービスにアクセスすること」が禁止行為として列挙されている。

#### ヤフーフリマ

[Yahoo!フリマ ガイドライン](https://paypayfleamarket.yahoo.co.jp/guide/guideline/) および [LY Corporation 利用規約](https://www.lycorp.co.jp/ja/company/terms/) で、サービス運営妨害目的のロボット利用および本来想定しないインターフェイス経由のアクセスが禁止されている。一次ソースの厳密な節番号は別途確認要 (TODO)。

#### ヤフオク

[Yahoo!オークション ガイドライン細則](https://auctions.yahoo.co.jp/topic/notice/policy/) でも自動化ツール・ロボットによる入札/出品が禁止されている。一次ソースの厳密な節番号は別途確認要 (TODO)。

### 検知の観点

各販路の bot 検知は大きく 3 層で構成されると考えられる。Cowork + Claude in Chrome と完全自動スクリプトの比較:

| 層 | 内容 | 完全自動スクリプト | Cowork + Claude in Chrome |
|---|---|---|---|
| 指紋層 | ブラウザの自動操作フラグ (`navigator.webdriver` 等) | フラグが立ち検知されやすい | Computer Use ベースで OS 入力経由のため**このフラグは立たない (この 1 点では有利)** |
| 拡張痕跡層 | Claude in Chrome 拡張固有の痕跡 | (該当なし) | **拡張 ID・稼働中に注入される DOM 要素 (停止ボタンコンテナ)・残留スタイル要素により、サイト側が「AI エージェント操作」と検知可能。Playwright にはない新たな検知ベクトル** |
| 行動層 | アクション間隔・操作の自然さ | 機械的 | 画面確認・対話で自然にバラつく |
| ボリューム層 | 1 セッションの出品数・速度 | いくらでも速くできる | 対話のため自然と数件/セッションに収まる |

**重要**: 「普段の Chrome だから実ユーザーと区別しにくく有利」とは**言えない**。`navigator.webdriver` 面では Playwright より有利だが、Claude in Chrome 拡張は専用の検知可能な痕跡を DOM に残す (セキュリティベンダー CHEQ が検知手法を公開済み)。メルカリは不正検知専門チーム (TnS) を持つため、拡張検知を導入する可能性は否定できない。**総合的には Cowork が一概に有利とは言えない**。検知の可能性はゼロではないため、本手順の他の制約 (出品ペース等) を必ず厳守すること。

### UI 変更への耐性

各販路は定期的に UI を変更する。Claude in Chrome は画面を見て判断するため、ボタンの位置や文言が多少変わっても臨機応変に対応できる (固定スクリプトのように壊れない)。

## 前提条件

### 環境

- Claude Cowork が利用可能 (Pro 以上の有料 Anthropic アカウント)
- Google Chrome (または Microsoft Edge) に Claude in Chrome 拡張がインストール済み
- この `reselling` リポジトリのローカルフォルダに Cowork からアクセスできる (CSV・画像を読むため)

### アカウント

販路ごとの事前準備を完了させておく。未完了だと出品の途中でブロックされる。

- **メルカリ**: 個人アカウント作成済み + **本人確認完了** + Chrome でログイン済み
- **ヤフーフリマ**: Yahoo! JAPAN ID 作成済み + **本人情報の登録完了** (氏名/カナ/電話/郵便番号/住所) + Chrome でログイン済み
- **ヤフオク**: Yahoo! JAPAN ID 作成済み + **出品者情報の登録完了** + **Yahoo!ウォレット登録完了** (PayPay 連携または受取銀行口座) + Chrome でログイン済み。Yahoo! JAPAN ID はヤフーフリマと共通
- **一度ログインすればブラウザにセッションが残るため、出品のたびに再ログインする必要はない**

### 入力データ

各「出品バッチ」(=同時期に出品する商品群) は次のディレクトリ構造で配置する:

```
listings/runs/YYYY_MM_DD/
├── YYYY_MM_DD_listing.csv     # 出品予定リスト (本手順の入力)
├── status.json                # 出品状態の管理ファイル (初回はファイル無しで OK)
└── {id}/                      # 各 id ごとの画像ディレクトリ
    ├── image1.jpg
    └── ...
```

- `YYYY_MM_DD` は出品バッチを開始する日付 (JST)
- `{id}` は CSV の `id` カラムに対応する 3 桁ゼロ埋め連番 (`001`, `002`, ...)
- CSV のスキーマは [§ CSV 仕様](#csv-仕様)、画像は [§ 画像の要件](#画像の要件) を参照

## 制約事項 (必読、BAN 対策)

各販路は出品ペースや内容の異常を検知するとアカウントを段階的に制限する (警告 → 一時利用制限 → 無期限利用停止)。以下を厳守する。

### 1. 出品ペース

[メルカリ運営公式の出品ポイント PDF](../references/%E3%80%90%E5%87%BA%E5%93%81%E3%81%AE%E3%83%9D%E3%82%A4%E3%83%B3%E3%83%88%E3%83%BB%E6%B3%A8%E6%84%8F%E7%82%B9%E3%80%91.pdf) には次の 2 つの上限が示されている (両方守る):

- **短時間上限**: 10〜30 分以内に 10 件以上の出品・削除は NG
- **1 日上限**: 1 日トータルで 30〜50 件以上の出品・削除は NG

安全側に守るため、本手順では次の運用ルールを設ける:

| 運用ルール | 数値 | どの上限を防ぐか |
|---|---|---|
| 1 セッションでの出品数 | **5 件以内** | 短時間上限 |
| セッション間の間隔 | **最低 30 分** | 短時間上限 |
| 1 日トータル | **20 件以内** | 1 日上限 (PDF の 30〜50 件 NG ラインの 2/3) |
| 月 100 件のペース配分 | 上限 20 件/日の範囲で柔軟に運用 | 1 日上限の範囲内 |
| 同一商品の削除→再投入 | **本工程では行わない** | PDF「動作数」を温存。SEO 目的の再投入は SEO 工程の責務 |

1 セッション 5 件 + セッション間 30 分間隔なら、任意の 30 分窓に含まれる出品は最大 5 件のため短時間上限 (10 件) を必ず満たす。1 日 20 件以内で 1 日上限も満たす。

### 2. 自動化検知への意識

- 1 件出品するごとに**画面を確認**してから次に進む
- 機械的に連続操作せず、対話のテンポを保つ
- 出品終了時は無理にセッションを続けない

## CSV 仕様

### 重要: CSV はいかなる理由があろうと変更しない

`listing.csv` は run 開始時に確定したら、**いかなる理由があろうと変更してはいけない**。

- 商品情報に誤りが見つかった場合も CSV を直接書き換えない
- 出品済み・出品失敗などの状態を CSV に書き戻さない (状態は [`status.json`](#状態管理-statusjson) で管理)
- 商品の追加が必要な場合は新しい run ディレクトリを作り直す
- Cowork は本工程の実行中、いかなる場合も `listing.csv` への書き込み・編集を行わない

### スキーマ

`listings/runs/YYYY_MM_DD/YYYY_MM_DD_listing.csv` は UTF-8、ヘッダー行付き。各セルが改行を含む場合はダブルクォートで囲む (RFC 4180 準拠)。

| カラム | 必須 | 内容 | 制約・例 |
|---|---|---|---|
| `id` | ◎ | run 内一意の識別子 | 3 桁ゼロ埋め連番 (`001`〜`999`) |
| `商品名` | ◎ | 出品タイトル | 40 文字以内 |
| `商品の説明` | ◎ | 説明文 (改行可) | 1000 文字以内 |
| `カテゴリー1`〜`カテゴリー4` | ◎ | カテゴリー階層 | 例: `ファッション` / `メンズ` / `トップス` / `その他` |
| `サイズ` | ◎ | カテゴリー依存のサイズ | 例: `L`、`27.5cm`、`Free` |
| `商品の状態` | ◎ | 6 段階のいずれか | `新品、未使用` / `未使用に近い` / `目立った傷や汚れなし` / `やや傷や汚れあり` / `傷や汚れあり` / `全体的に状態が悪い` |
| `配送料の負担` | ◎ | 通常は出品者負担 | `送料込み(出品者負担)` |
| `配送の方法` | ◎ | 配送業者・サービス | 例: `ゆうゆうメルカリ便`、`らくらくメルカリ便` |
| `送料` | ◎ | 出品判断時に確定済みの送料 (整数の円) | 例: `215`、`410`、`750`。ヤフオクのサブサービス選択に使う |
| `発送元の地域` | ◎ | 47 都道府県のいずれか | 例: `和歌山県` |
| `発送までの日数` | ◎ | 3 段階のいずれか | `1~2日で発送` / `2~3日で発送` / `4~7日で発送` |
| `価格` | ◎ | 整数 (円) | 300 以上 |
| `商品の特徴` | △ | カテゴリー依存の特徴項目 | 例: `汚れ・破れ・臭いなど: なし` |
| `画像1`〜`画像20` | ◎ (最低 1) | 画像の CSV からの相対パス | 例: `001/image1.jpg` |

- `画像1` が各販路のサムネイル画像になる。`画像1`〜`画像20` のカラム順がアップロード順
- 必要な枚数だけ埋め、残りは空欄でよい

### 販路別の値マッピング

CSV はメルカリ用語をベースにして書く。販路差は出品時に Cowork が下表で変換する。

| CSV カラム | CSV 値 (メルカリ準拠) | メルカリ | ヤフーフリマ | ヤフオク |
|---|---|---|---|---|
| 配送の方法 | `ゆうゆうメルカリ便` | ゆうゆうメルカリ便 | おてがる配送（日本郵便） | おてがる配送 (日本郵便系) |
| 配送の方法 | `らくらくメルカリ便` | らくらくメルカリ便 | おてがる配送（ヤマト運輸） | おてがる配送 (ヤマト系) |
| 発送までの日数 | `1~2日で発送` | 1~2日で発送 | 1~2日 | 1〜2日 |
| 発送までの日数 | `2~3日で発送` | 2~3日で発送 | 2~3日 | 2〜3日 |
| 発送までの日数 | `4~7日で発送` | 4~7日で発送 | 3~7日 | 3〜7日 |
| 商品の状態 | `新品、未使用` | 新品、未使用 | 未使用 | 未使用 |
| 商品の状態 | `未使用に近い` | 未使用に近い | 未使用に近い | 未使用に近い |
| 商品の状態 | `目立った傷や汚れなし` | 目立った傷や汚れなし | 目立った傷や汚れなし | 目立った傷や汚れなし |
| 商品の状態 | `やや傷や汚れあり` | やや傷や汚れあり | やや傷や汚れあり | やや傷や汚れあり |
| 商品の状態 | `傷や汚れあり` | 傷や汚れあり | 傷や汚れあり | 傷や汚れあり |
| 商品の状態 | `全体的に状態が悪い` | 全体的に状態が悪い | (該当なし) → ユーザーに質問 | 全体的に状態が悪い |

ヤフオクの配送方法はサブサービス (ゆうパケット等) を **CSV `送料` 列の値から逆引き**して決める:

| CSV `送料` 値 | ヤフオクで選ぶサブサービス (日本郵便系) | 制約 |
|---|---|---|
| 160 | ゆうパケットポストmini | 16.8×21.1cm 内、専用封筒、2kg まで |
| 210 | ゆうパケットポスト | 60cm 内、専用箱/シール、2kg まで |
| 215 | ゆうパケット | 60cm 内、厚さ 3cm まで、1kg まで |
| 410 | ゆうパケットプラス | 24×17cm 内、専用箱、厚さ 7cm まで、2kg まで |
| 750 以上 | ゆうパック | 170cm 内、25kg まで |

ヤマト系 (CSV が `らくらくメルカリ便`) も同様に送料から逆引き (ネコポス 210 / 宅急便コンパクト 490 / 宅急便 750〜)。

**CSV `送料` が空欄の場合は出品判断ワークフロー上のバグ**なので、Cowork は推測せず必ずユーザーに質問してから出品する。

### CSV にない販路独自項目 (ヤフーフリマ)

ヤフーフリマはカテゴリ選択直後に動的な属性枠が出る (例: メンズトップスなら ブランド/性別/色/着用回数/サイズ S/M/L)。CSV に列がない。

**ブランドは原則として空欄にする。** 本プロジェクトの中国輸入物販はノーブランド品が大半なので、ブランド欄は**デフォルトで空欄が正しい状態**である。例外は CSV・商品名・商品説明に明確なブランド名が記載されている場合のみで、そのときだけそのブランドを入力する。販路が商品名から自動推定したブランドは誤りが多いため、まず削除してから上記の基準で判断する (推定値をそのまま採用しない)。

ブランド以外の属性の入力方針 (上から順に判定):

1. **CSV / 商品名 / 商品説明から確度高く値が決まる** → その値を入力 (例: 説明に「カラー: ブラック」→ 色「黒」)
2. **商品にその属性が存在しないと判断できる** → 空欄のまま進める (ユニセックス商品 → 性別空欄、新品出品なのに着用回数項目がある → 空欄 等)
3. **推測になる (確度が低い)** → ユーザーに項目と候補を提示して質問
4. **判定不能** → ユーザーに質問

適当に埋めない。判断に迷ったら 3/4 として必ず質問する。

### CSV にない販路独自項目 (ヤフオク)

| 項目 | 値 | 理由 |
|---|---|---|
| 販売形式 | **フリマ（定額）** に切替 | デフォルトはオークション。中国輸入物販はオークション運用しない |
| 終了する日時 (日付) | **3 日後** | [SEO PDF](../references/%E5%90%84%E3%83%95%E3%83%AA%E3%83%9E%E3%82%B5%E3%82%A4%E3%83%88%E3%81%AESEO%E3%81%AE%E3%82%84%E3%82%8A%E6%96%B9.pdf) の推奨 (「3 日以内に設定する人が多い」) |
| 終了する日時 (時間帯) | **「午後 9 時から午後 10 時」** | 同 PDF「終了時間は 21-22 時頃に掲載終了がおすすめ」 |
| 送料負担 | 出品者 (デフォルトのまま) | CSV「配送料の負担」が `送料込み(出品者負担)` に対応 |

## 画像の要件

- 形式: JPG または PNG
- サイズ: 1 枚あたり 10MB 以下を推奨
- 枚数: 1 件あたり 1〜20 枚 (ヤフオクは最大 10 枚)

画像の中身 (実物撮影・加工範囲) は写真撮影・商品説明ページ作成工程で担保される前提。本工程では用意された画像をそのままアップロードする。

## 1 件あたりの出品フロー

Cowork が CSV を読みながら、以下を実行する。

### Step 1: 対象の選定

1. ユーザーから出品先の販路を確認する (`mercari` / `yahoo_flea` / `yahoo_auction`)
2. `listings/runs/YYYY_MM_DD/status.json` を読む (ファイル無し時は全 id × 全販路を `未出品` 扱い)
3. 選んだ販路について `status` が `未出品` の最初の id を選ぶ
4. CSV から該当行を読む
5. `{id}/` 配下の画像が CSV の `画像1`〜`画像N` と整合しているか確認
6. 文字数・必須項目を確認 (CSV はメルカリ準拠で検証):
   - 商品名 40 文字以内 / 商品の説明 1000 文字以内 / 価格 300〜300,000
   - 必須カラム (id, 商品名, 商品の説明, カテゴリー1〜4, サイズ, 商品の状態, 配送料の負担, 配送の方法, 送料, 発送元の地域, 発送までの日数, 価格, 画像1) が埋まっている

不備があれば中止してユーザーに報告。

### Step 2: フォーム入力

販路ごとに UI が違うので、選んだ販路の節を実行する。**操作はすべて「画面を見て、その要素をクリック/入力する」**。各ステップ後に画面が想定どおり変わったか確認してから次へ進む。

#### Step 2-A: メルカリ

1. Chrome で `https://jp.mercari.com/sell/create` を開く (ログインページに飛んだら [§ トラブル対応](#共通) 参照)
2. 「AI 出品サポート」のスイッチを **OFF にする** (ON だと画像から商品名・説明が自動生成され上書きされる)
3. 画像欄から `画像1`〜`画像N` を順にアップロードする (`画像1` がサムネ)
4. 「商品名」を入力 (40 文字以内)
5. 「カテゴリーを選択する」をクリックし、4 階層を順に選ぶ
6. (発生時のみ) 製品情報入力画面 (`/sell/wizard`) に飛んだら「出品画面に戻る」をクリック。入力済み項目は保持される
7. 「サイズ」を選択
8. 「商品の状態を選択する」から CSV の状態を選ぶ
9. 「商品の特徴」(汚れ・破れ等) を選ぶ。**「なし」を選ぶと説明文末尾に文言が自動追記される**
10. 「商品の説明」を入力する。**手順 9 の後に入力**して自動追記を上書きする
11. 「配送の方法を選択する」から CSV の配送方法を選び「更新する」
12. 「発送元の地域」「発送までの日数」を選択
13. 「価格」を入力 (300 以上)
14. **画面全体を見て全項目が想定どおりか確認** (画像枚数・商品名・カテゴリー・サイズ・状態・配送・地域・価格)
15. 「出品する」をクリック

#### Step 2-B: ヤフーフリマ

1. Chrome で `https://paypayfleamarket-sec.yahoo.co.jp/item/add?from=sellTop` を開く
2. 「画像を追加する」をクリック → 出たダイアログで「アルバムから選択する」をクリック → 画像を選択 (**2 段階。1 回目のクリックではファイル選択は開かない**)
3. 「商品名」を入力 (65 文字以内)
4. 「カテゴリ」をクリック → モーダル末尾の「他のカテゴリから選ぶ」→ 4 階層を辿って選ぶ (商品名から予測候補も出るが、「その他」相当を確実に選ぶには階層を辿る)
5. カテゴリ選択直後に**動的な属性枠** (ブランド/性別/色/着用回数/サイズ 等) が出る → [§ CSV にない販路独自項目 (ヤフーフリマ)](#csv-にない販路独自項目-ヤフーフリマ) の 4 段階方針で入力
6. **ブランドが自動で入っている場合** → 削除して、正しいブランドを検索し直して選ぶ (例: 「URBAN RESEARCH」が「URBAN RESEARCH DOORS」に誤推定される)。ノーブランドなら空欄
7. **ハッシュタグが自動で付いている場合** → 誤りなら削除する
8. 「商品の状態」を選ぶ (マッピング表で CSV 値を変換)
9. 「商品説明」を入力 (任意項目だが必ず CSV の値を入れる)
10. 「配送方法」をクリック → マッピング表のヤフマ値 (おてがる配送 日本郵便/ヤマト) を選ぶ (親サービスのみ)
11. 「発送までの日数」を選ぶ (マッピング表で変換)
12. 「発送元の地域」を選ぶ
13. 「販売価格」を入力 (300〜300,000)
14. **画面全体を見て全項目を確認** (動的属性枠も含む)
15. 「出品する」をクリック (本人情報未登録時は「あなたの情報」ダイアログ → [§ ヤフーフリマ固有](#ヤフーフリマ固有))

#### Step 2-C: ヤフオク (フリマ形式)

1. Chrome で `https://auctions.yahoo.co.jp/sell/jp/show/submit` を開く
2. キャンペーン (PayPay マツリ等) のポップアップが出ていたら**×ボタンで閉じる** (手前に被さって操作を妨害する)
3. **販売形式を「フリマ（定額）」に切り替える** (デフォルトはオークション)
4. 画像欄から画像を順にアップロード (最大 10 枚)
5. 「商品名」を入力 (65 文字以内)
6. 「カテゴリ」の「選択する」をクリック → 別ページで商品名から候補が出る → 適切な行を選ぶ → **「このカテゴリに出品」ボタンを押して確定** (行クリックだけでは確定しない) → 出品フォームに戻る。階層が深く「その他」相当が無いことが多い。迷えばユーザーに質問
7. 「商品の状態」を選ぶ (マッピング表で変換)
8. 「説明」欄をクリックして CSV の説明文を入力する (リッチテキスト欄。普通にクリックして入力すればよい)
9. 「発送元の地域」を選ぶ
10. 「送料負担」は「出品者」がデフォルトで選択済み (CSV と一致するので通常は変更不要)
11. 「配送方法」(おてがる配送) で、**CSV `送料` 列の値から逆引き**してサブサービスを選ぶ ([§ 販路別の値マッピング](#販路別の値マッピング) の逆引き表参照)
12. 「支払いから発送までの日数」を選ぶ (マッピング表で変換)
13. **「終了する日時」: 日付は 3 日後、時間帯は「午後 9 時から午後 10 時」を選ぶ** (SEO 推奨)
14. 「価格」を入力 (300 円以上)
15. **画面全体を見て全項目を確認**
16. 「確認する」をクリック → 確認画面に遷移 (入力漏れがあればフィールドに戻される)
17. 確認画面で「**出品する**」をクリック (出品者情報・Yahoo!ウォレットが未登録だと「出品する」が出ず登録リンクが表示される → [§ ヤフオク固有](#ヤフオク固有))

### Step 3: 完了処理

1. 完了画面を確認 (メルカリ: 「出品が完了しました」/ ヤフマ・ヤフオク: 出品完了ページへ遷移)
2. 出品した商品ページの URL から item ID を取得:
   - メルカリ: `https://jp.mercari.com/item/m{12 桁}`
   - ヤフーフリマ: `https://paypayfleamarket.yahoo.co.jp/item/z{9 桁}`
   - ヤフオク: `https://auctions.yahoo.co.jp/jp/auction/{a-z}{10 桁}` (例: `o1164929607`)
3. `status.json` の該当販路ノードを更新 (スキーマは [§ 状態管理](#状態管理-statusjson))

### Step 4: 次に進むか、セッションを終了するか

- 続けて出品する場合: **最低 30 分待機**してから Step 1 へ戻る
- 5 件出品済み、または 30 分間隔を空けにくい → セッション終了。次は最低 30 分後 (推奨: 数時間後または翌日)

## 状態管理: `status.json`

CSV (出品予定リスト) は不変として扱い、状態は別ファイル `status.json` で管理する。

### スキーマ

販路別に独立した出品状態を持つ。

```json
{
  "<id>": {
    "<channel>": {
      "status": "未出品 | 出品済み | 出品失敗",
      "item_id": "<販路の item ID>",
      "listed_at": "2026-05-10T15:50:00+09:00",
      "failed_at": "2026-05-10T16:00:00+09:00",
      "failure_reason": "<理由>"
    }
  }
}
```

- `<channel>` は `mercari` / `yahoo_flea` / `yahoo_auction`
- `status` のみ全状態で必須。`item_id`・`listed_at` は `出品済み` 時のみ。`failed_at`・`failure_reason` は `出品失敗` 時のみ
- 日時は ISO 8601 + JST オフセット (`+09:00`)
- `item_id` 形式: メルカリ `m{12桁}` / ヤフマ `z{9桁}` / ヤフオク `{a-z}{10桁}`

例 (id=001 をメルカリ出品済み・他販路未出品):

```json
{
  "001": {
    "mercari": { "status": "出品済み", "item_id": "m10468438509", "listed_at": "2026-05-10T15:50:00+09:00" },
    "yahoo_flea": { "status": "未出品" },
    "yahoo_auction": { "status": "未出品" }
  }
}
```

### `status.json` が無い場合 / 販路ノードが無い場合

初回は全 id × 全販路を `未出品` 扱い。販路ノードが無い id もその販路は `未出品`。Step 3 で初めて出品成功した時点で Cowork が該当販路ノードを作成・更新する。

## トラブル対応

### 共通

#### ログインしていない / セッション切れ
- 症状: 出品フォームを開いたらログインページが表示された
- 対処: **ユーザーが Chrome で手動ログイン** (2 段階認証含む)。一度ログインすればセッションが残るので次回以降は不要。Cowork はログイン情報を入力しない

#### 「出品する」が押せない (グレーアウト)
- 原因: 必須項目漏れ
- 対処: 画面全体を見て、未入力の項目を埋める

#### 画像アップロード失敗
- 確認: 枚数が上限超過 (メルカリ/ヤフマ 20 枚、ヤフオク 10 枚) でないか、ファイルが極端に大きく (50MB 超) ないか、JPG/PNG か
- 対処: 該当画像を差し替え/削除して再試行

#### 出品ペースの累積警告
- 症状: 「短時間に多くの出品をされています」等の警告
- 対処: その日の出品を**中止**。最低 24 時間休止してから再開

### メルカリ固有

#### 製品情報入力画面 (wizard) に飛ぶ
- 症状: カテゴリー選択直後に製品情報・モデル入力画面に遷移 (「その他」を含むカテゴリーで発生)
- 対処: 「出品画面に戻る」をクリック。入力済み項目は保持される

#### 「商品の特徴」で説明文が自動追記される
- 症状: 「商品の特徴」で「なし」を選ぶと説明文末尾に `汚れ・破れ・臭いなど...なし` が追記される
- 対処: 「商品の特徴」を選んだ**後**に「商品の説明」を入力し直して上書きする (Step 2-A の順序がこのため)

#### item ID が読めない
- 対処: マイページ `https://jp.mercari.com/mypage/listings` を開き、最新の出品ページの URL から item ID を取得

### ヤフーフリマ固有

#### 「あなたの情報」ダイアログ (本人情報未登録)
- 症状: 「出品する」押下後に氏名・住所等の入力ダイアログが出て止まる
- 対処: **ユーザーが**ダイアログに入力して「登録して出品する」を押す。または事前にプロフィール画面で本人情報を登録してからやり直す。**Cowork は個人情報を入力しない**

#### ブランドが自動で誤った値になる
- 症状: 商品名から別レーベルが推定される (「URBAN RESEARCH」→「URBAN RESEARCH DOORS」)
- 対処: ブランド欄を削除し、正しいブランドを検索して選び直す。ノーブランドなら空欄

#### ハッシュタグが自動で付く
- 対処: 誤ったハッシュタグを削除する。ブランド修正で追従する場合もあるが念のため確認

#### カテゴリ選択後に未知の属性枠が出る
- 対処: [§ CSV にない販路独自項目 (ヤフーフリマ)](#csv-にない販路独自項目-ヤフーフリマ) の 4 段階方針に従う

#### item ID が読めない
- 対処: マイページの出品一覧から最新の出品ページに遷移し、URL `https://paypayfleamarket.yahoo.co.jp/item/z{9 桁}` から取得

### ヤフオク固有

#### キャンペーンのポップアップが操作を妨害する
- 症状: フォーム表示直後に PayPay マツリ等のポップアップが手前に出て、画像追加や販売形式切替が押せない
- 対処: ポップアップの**×ボタンをクリックして閉じる**

#### 販売形式がオークションのまま
- 症状: 何もしないとオークション形式で出品される
- 対処: **販売形式を「フリマ（定額）」に必ず切り替える**

#### カテゴリが確定しない
- 症状: カテゴリ階層の行をクリックしただけでフォームに戻り、カテゴリ未確定
- 対処: 行を選んだ後、必ず「このカテゴリに出品」ボタンを押して確定する

#### 出品者情報・Yahoo!ウォレット未登録で「出品する」が出ない
- 症状: 確認画面で「出品する」の位置に登録リンクが表示される
- 対処: ユーザーが事前に出品者情報と Yahoo!ウォレットを登録する ([§ 前提条件 - アカウント](#アカウント))。未登録アカウントではヤフオク出品不可

#### item ID が読めない
- 対処: マイオーク `https://auctions.yahoo.co.jp/jp/show/mystatus` の出品中一覧から最新の出品ページに遷移し、URL `https://auctions.yahoo.co.jp/jp/auction/{a-z}{10 桁}` から取得

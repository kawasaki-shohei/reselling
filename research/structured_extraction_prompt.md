# 第 5 段階 (structured_extraction_step) プロンプト

## 【絶対禁則】ファイル操作の制約

以下を厳守。違反は仕様違反として扱う。

1. **指定出力パス以外にファイルを作成しない**
   - 出力パスは Agent 起動時に指示される
   - 中間ファイル・デバッグファイルを勝手に作らない
2. **入力ファイルを書き換えない**
   - 入力 TSV はすべて読み取り専用として扱う
3. **プロジェクト内の他ファイルを変更しない**
   - Edit / Write / NotebookEdit は、指定出力パスへの 1 回の書き込みのみに使う
   - 他の変更が必要になった場合は実行せず、プロンプト発行者に報告する
4. **違反しそうな操作は実行せず報告する**

## タスク

メルカリの商品タイトルから、**同一商品判定と後段クラスタリングに必要な構造化情報**を抽出して JSON で返す。

入力 TSV は 3 カラム: `rowIndex \t id \t name`。

出力フィールドは 8 つ (rowIndex + id + name + 5 属性):

| フィールド | 意味 | 必須 |
|---|---|---|
| `rowIndex` | 入力 TSV の 1 列目の数字をそのままコピー | 必須 |
| `id` | 入力 TSV の 2 列目 (item ID、例: `m12345678901`) をそのままコピー | 必須 |
| `name` | 入力 TSV の 3 列目 (タイトル文字列) をそのままコピー | 必須 |
| `category` | 粗いジャンル (パンツ / タオル / クリーム / ネックレス 等)。判定不能なら `null` | 必須 |
| `subcategory` | category に用途・機能修飾を足した細かい名前 (ハーフパンツ / ビーチタオル / ハンドクリーム 等)。修飾が無ければ `null` | 任意 |
| `color` | 色、配列 (タイトル明記時のみ、無ければ `null`) | 任意 |
| `size` | サイズ (無ければ `null`) | 任意 |
| `quantity` | 個数・セット枚数・容量 (無ければ `null`) | 任意 |

**v3 から除外されたフィールド**: `pattern` (柄) と `material` (素材) は第 6 段階で画像判定と合わせて抽出する。

---

## 【最重要】統一を守ること、その目的

この段階の出力は後段で「category/subcategory が同じ行を束ねて、画像判定の単位にする」ために使われる。**同じ意味の語を別行で別表記にすると束ねられなくなり、同じ商品なのに取りこぼす**。

よって以下を厳守する:

1. **同じ概念には必ず同じ表記を使う** (Tシャツ と ティーシャツ を混在させない、シール と ステッカー を混在させない)
2. **1 行ずつ独立処理されるが、全行を通じて語彙を揃える努力をする**
3. **完全統一は諦めてよい**。プロンプトに書かれた自明な揺れだけ統一し、それ以外はタイトル原文のまま出力する。最終工程 (normalization_step) で残差を揃える

---

## category と subcategory

### category (粗いジャンル)

「ハーフパンツ」と「パンツ」は **同じ category = "パンツ"** にする。違いは subcategory で表現する:

| タイトル例 | category | subcategory |
|---|---|---|
| ハーフパンツ メンズ M | パンツ | ハーフパンツ |
| 女の子 ショーツ 100cm | ショーツ | null |
| ビーチタオル 大判 | タオル | ビーチタオル |
| バスタオル 2枚セット | タオル | バスタオル |
| ハンドクリーム 50g | クリーム | ハンドクリーム |
| ショルダーバッグ 黒 | バッグ | ショルダーバッグ |
| 3D 立体シール 3枚 | シール | 3Dシール |
| ネイルチップ 量産型 | ネイルチップ | null |
| ゲルクッション ハニカム | クッション | ゲルクッション |

### category が判定不能なら null

- タイトルからジャンルが確定できないときは `null`
- `"その他"` / `"不明"` / 推測で何か書く、は禁止
- 後段 (第 6 段階) で画像から判定するので、無理に書かない

### subcategory は用途・機能修飾語を含むとき使う

- category と subcategory の文字列が同じになる場合は subcategory は `null`

### category 命名のメタルール

統一用語の固定リストは **提供しない**。以下のメタルールで命名する:

1. **カタカナ優先** (鏡 → ミラー)
2. **長音符なし優先** (ヘアーキャッチャー → ヘアキャッチャー)
3. **複合名詞は 1 語扱い** (クッションカバー、キーホルダー)
4. **短く、一般的な日本語で**
5. **自分が既に使った category は、別の行でも同じ形で書く**

## color (色、配列)

タイトルに色が明記されているときのみ採用。

### 統一する対象 (メタルールで判断)

固定の色辞書は持たない。以下のメタルールで判断する。

1. **日本語の漢字色名 (1〜2 文字) → 対応するカタカナ表記**
   例: 黒→ブラック / 白→ホワイト / 灰→グレー / 紺→ネイビー / 紫→パープル / 黄→イエロー / 橙→オレンジ / 桃→ピンク / 茶→ブラウン
   (例は説明用。漢字色名と判断したら同じパターンで処理する)

2. **英語の色名 → 対応するカタカナ表記**
   例: BLACK→ブラック / GRAY/GREY→グレー / PURPLE→パープル / ORANGE→オレンジ / NAVY→ネイビー
   大小文字・全角半角を問わず、英語色名と判断したら対応するカタカナに

3. **「○色」接尾辞は除去**
   例: 黒色→ブラック / カーキ色→カーキ

4. **「○色」(○ は単漢字) のパターン → 対応する一般カタカナ色に変換**
   例: 水色→ライトブルー / 桜色→ピンク / 茜色→レッド / 桃色→ピンク / 草色→グリーン / 空色→ライトブルー
   (「○色」というパターンを認識したら、○ の漢字から想起される一般的なカタカナ色に統一)

### 統一しない対象 (タイトル原文のままコピー)

1. **辞書に無い単独色名** (カーキ / テラコッタ / モカ / マスタード / ミント / チャコール / ラベンダー / ベージュ / アイボリー / コーラル 等)
   勝手に近い色に寄せない
2. **複合色名・修飾付き色名** (ダークグレー / オフホワイト / ライトブルー / シエラブルー / シャンパンゴールド 等)
   既出のシンプル色 (グレー / ホワイト / ブルー) があっても揃えない
3. **判断に迷うもの**
   原文ママ。最終統一は normalization_step で行う

### 出力形式

- **必ず配列で出力**。単一色でも `["ブラック"]`
- 複数色: `["ベージュ", "ブラック"]`
- タイトルに色が書かれていなければ `null` (空配列ではない)

---

## size (サイズ)

タイトル内のサイズ表記を以下のルールで整理する。

### 自明な機械翻訳のみ統一する

| 入力 | 統一形 | 理由 |
|---|---|---|
| Ｍサイズ / Mサイズ / Ｍ | M | 全角半角、「サイズ」接尾辞除去 |
| Ｓ / Ｌ / ＸＬ / ＬＬ | S / L / XL / LL | 全角半角 |
| 100ｃｍ / 100CM | 100cm | 全角半角、大小文字 |
| FREE / ワンサイズ | フリー | 英語・類似表現のカタカナ化 |

### category から単位補完する

category が確定していて、タイトルに数値しか書かれていない場合は単位を補う:

- category = 子供服・ベビー系 (ショーツ, パンツ, Tシャツ, ワンピース, 水着 等) + 「90」「100」「110」「120」「130」「140」 → `90cm` `100cm` ...
- category = 靴 + 「23」「25.5」 → `23cm` `25.5cm`

**category が null の場合、単位が曖昧な数値は size に入れない** (`null`)。ただしタイトルに「A4 サイズ」「L サイズ」など単位・記号が明示されていれば残す。

### それ以外はタイトル原文のままコピー

- 「26 インチ」「B70」「US 6」「UK6」「180×200」など、辞書外の特殊表記はタイトル表記のままコピー
- 範囲表記 (「M〜L」「19〜23cm」) はそのまま
- 最終統一は normalization_step で行う

### 判断基準

「Mサイズ → M」のような自明な揺れだけ統一する。それ以外は悩まずそのままコピー。

---

## quantity (個数・セット枚数・容量)

タイトル内の数量表記を以下のルールで整理する。

### 自明な機械翻訳のみ統一する

| 入力 | 統一形 | 理由 |
|---|---|---|
| 2枚入り / 2枚入 | 2枚 | 「入り/入」接尾辞除去 |
| 3枚組 / 3枚セット / 3点セット | 3枚セット | 「組/点」を「枚セット」に統一 |
| 500グラム | 500g | カタカナ→記号 |
| 1キロ | 1kg | 同上 |

### それ以外はタイトル原文のままコピー

- 「30ml × 3本」「業務用 100 枚」「お得用 500 枚」「2 連」「4 包」「5 束」など、辞書外の表記はタイトルのまま
- 最終統一は normalization_step で行う

### 判断基準

- 単品 (1 つだけの商品) は `null`
- 数値単独で単位不明 (タイトルに「3」だけ) は `null`
- 「組/点 → 枚セット」のような自明な揺れだけ統一。それ以外は悩まずそのままコピー

---

## 【絶対ルール】推測で埋めない

タイトルに書かれていない属性は `null`。

- 「ショーツ M」→ color は書かれていないので `null`
- 「キャリーバッグ 折りたたみ」→ quantity は書かれていないので `null`
- 画像から推測するような属性は全部 `null`

例外: size は category から単位補完する (上記ルール通り)。ただし「書かれていないサイズを想像で書く」は禁止。

---

## 【絶対ルール】rowIndex と id と name はそのままコピー

- `rowIndex`: 入力 TSV の 1 列目の数字をそのままコピー。振り直さない
- `id`: 入力 TSV の 2 列目 (item ID) をそのままコピー。加工・補正禁止
- `name`: 入力 TSV の 3 列目 (タイトル) をそのままコピー。装飾・絵文字も残す

---

## 【重要】前段語彙整合 (prior_vocabulary_alignment_substep)

プロンプトの末尾に `【前段までに使われた語彙】` セクションがあれば、以下の手順で自分の出力を見直す。

### 対象フィールド

前段語彙整合は **category と subcategory のみ** を対象とする。**color は対象外** (color は本仕様の「color (色、配列)」セクションのメタルールで処理済み。vocab を参照しない)。

### 手順

1. 自分が抽出した category / subcategory のユニーク値を把握する
2. vocab リスト (前段の既出語) と突き合わせる
3. 自分の語と同義の既出語があれば、**vocab の表記に合わせる** (揺れを揃える)
4. vocab に無い新しい語はそのまま (新しく追加される)

### 同義判定の基準

意味ベースで判定するが、**慎重に判定する**。少しでも意味が違えば揃えない。

#### 揃えてよい例 (純粋な表記揺れ)

- category 「生地」と vocab の「ファブリック」 → 同義、既出の「ファブリック」に揃える
- category 「Tシャツ」と vocab の「ティーシャツ」 → 同義、既出の「ティーシャツ」に揃える
- category 「バッグ」と vocab の「かばん」 → 同義、既出の「かばん」に揃える

#### 揃えてはいけない例 (subcategory の派生違い)

以下のような「同じ系統だが用途・形状・対象が違う」ペアは絶対に揃えない:

- 「パスポートケース」と vocab 「パソコンケース」 → 揃えない (用途違い: 旅券保護 vs 機材収納)
- 「ハーフパンツ」と vocab 「ロングパンツ」 → 揃えない (形状違い: 短い vs 長い)
- 「ノートパソコンスタンド」と vocab 「ブックスタンド」 → 揃えない (用途違い: 機材支持 vs 本立て)
- 「レギンス」と vocab 「ガウチョパンツ」 → 揃えない (形状違い: ピチピチ vs ゆったり)
- 「ハンドクリーム」と vocab 「ヘアクリーム」 → 揃えない (対象部位違い: 手 vs 髪)
- 「ショルダーバッグ」と vocab 「リュック」 → 揃えない (持ち方違い: 肩掛け vs 背負い)

**判断基準**: 用途・形状・対象部位・接続方式・素材・サイズ感 のいずれかが違えば、たとえ同じ系統でも揃えない。**確信が無ければ揃えない**。

#### 迷ったら揃えない

少しでも意味が違うかもと思ったら揃えず原文ママでコピー。下流の normalization_step が表記揺れだけ統一する。

### vocab セクションが無い場合

プロンプト末尾に vocab セクションが無ければ (これは初回 agent の場合)、自分の chunk 内で同義語の混在を避けることだけ意識する。

## やってはいけない失敗パターン

1. 同じ category を別行で別表記にする (「シール」と「ステッカー」の混在、「Tシャツ」と「ティーシャツ」の混在)
2. 判定不能な category を `"その他"` / `"不明"` / 推測で埋める (必ず `null`)
3. 色・size・quantity を **推測で** 埋める (書かれていないのに想像で入れる)
4. 辞書外の色 (カーキ / テラコッタ 等) を勝手に近い色に寄せる (そのままコピーする)
5. size の単位補完で誤判断 (category=null なのに「90」を `90cm` にする等)
6. rowIndex を 1, 2, 3 と振り直す
7. JSON エスケープをサボる (タイトルの `\` を `\\` にしない)
8. name / id に装飾を付け足したり削ったりする
9. 前段語彙整合を無視して、自分流の表記を貫く

---

## 迷った時の判断基準

- **category の粒度で迷う**: 「ピアス」か「アクセサリー」か → **より具体的な方を使う**
- **category と subcategory の切り分けで迷う**: 「ショーツ」と「ハーフパンツ」はどちらが category か → **ショーツは衣類の独立ジャンル、ハーフパンツは「パンツ」の一種**
- **複雑な修飾語**: 装飾・煽り語 (可愛い / 大人気 / セール / 新品 / 即日発送) は全部無視
- **タイトル内で属性が重複**: 「白T … ホワイト XL」→ 色を 1 つに統一して `["ホワイト"]`
- **色が 2 つ書かれている**: `["ベージュ", "ブラック"]`
- **ここに書かれていない揺れで迷ったら**: タイトル原文のままコピーして、normalization_step に任せる

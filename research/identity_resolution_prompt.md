# 第 6 段階 工程 6-2 (同一商品判定) プロンプト

## 【絶対禁則】ファイル操作の制約

以下を厳守。違反は仕様違反として扱う。

1. **指定出力パス以外にファイルを作成しない**
   - 出力パスはプロンプト末尾「## 指定出力パス」セクション参照
   - 中間ファイル・デバッグファイルを勝手に作らない
2. **入力ファイルを書き換えない**
   - 仮クラスタ情報、画像 webp はすべて読み取り専用として扱う
3. **プロジェクト内の他ファイルを変更しない**
   - Edit / Write / NotebookEdit は、指定出力パスへの 1 回の書き込みのみに使う
   - 他の変更が必要になった場合は実行せず、プロンプト発行者に報告する
4. **違反しそうな操作は実行せず報告する**

## タスク

与えられた「仮クラスタ」内の N 件 (2〜50 件) の商品が、画像とタイトルを見て **本当に同じ商品か別商品か** を判定する。

N 件の商品は既に以下の 6 属性で完全一致している:
`category`, `subcategory`, `color`, `size`, `quantity`, `pattern`

これらの属性が同じでも、以下のような違いが残る可能性があるので、画像とタイトルから細分化する:

- **柄の具体バリエーション**: 「花柄」同士でもバラ / ひまわり / 桜 / 和花
- **形状の微差**: 同じ subcategory でも細かい形・カットが違う
- **素材の質感**: 本革 vs 合皮、綿 vs ポリエステル、透明ビニール vs OPP
- **用途や機能の違い**: 同じ属性でも実体の用途が異なる (旅券ケース vs パスポート風小物入れ)
- **プリント・ロゴの違い**: 無地でもロゴ位置やワンポイント刺繍の有無

## 同一商品判定の一般則 (重要)

**中国輸入品はタイトル・画像・説明文を故意に変える慣習がある** (通報回避)。よって以下:

- タイトルが違っても、画像を見て実体が同じなら **同一商品**
- 画像のアングルや背景が違っても、商品自体が同じなら **同一商品**
- 逆に、タイトルが似ていても画像を見て実体が違うなら **別商品**

判定軸は [`docs/research/mercari/judgment_examples/README.md`](../docs/research/mercari/judgment_examples/README.md) L13 の実体属性一覧:
**色・サイズ・個数・セット・素材・用途・柄**。この軸で違いがあれば別商品。

## 入力フォーマット

プロンプト末尾の「## 仮クラスタ」セクションに以下の情報が示される:

- `groupId`: このグループの ID
- `groupKey`: このグループを作った属性キー (参考情報)
- `items`: このグループの商品 N 件の配列。各要素は `{rowIndex, id, name, imagePath, attributes}`
  - `imagePath`: 画像絶対パス (Read ツールで開く)
  - `attributes`: category/subcategory/color/size/quantity/pattern/material (material は 6 軸に含まれていないので値が異なる場合あり)

## 作業手順

1. プロンプト末尾の「## 仮クラスタ」セクションを確認して items の件数を把握
2. items の各行について `imagePath` を Read して画像を取得
3. タイトル + 画像 + attributes (特に material) を見て、どれとどれが同じ商品かを判定
4. グループ分けした結果を後述の「## 出力フォーマット」で指定出力パスに 1 回で書き込む

## 出力フォーマット

```json
{
  "groupId": 123,
  "groupKey": "category=ショーツ|...",
  "subgroups": [
    {
      "subgroupId": 1,
      "rowIndexes": [163, 822],
      "reason": "両方無地の女児用ショーツ、画像が酷似、同一商品と判定"
    },
    {
      "subgroupId": 2,
      "rowIndexes": [491],
      "reason": "画像を見るとワンポイント刺繍あり、他と別デザイン"
    }
  ]
}
```

### 出力ルール

- `subgroupId` は 1 から始まる連番
- 各 subgroup の `rowIndexes` の和集合が仮クラスタの全 rowIndex と一致 (過不足なし、重複なし)
- `reason` は判定根拠を簡潔に (日本語 1 文、40 字程度)
- 全件が同一商品なら subgroup は 1 つ、全件が別商品なら N 個の subgroup (各 1 件)

## 確信できないときの扱い

- 画像が不鮮明で判断困難な場合は、その 1 件を **単独の subgroup** にする (他と合流させない)
- 迷ったら分ける (偽陽性 = 別商品を同じにまとめるリスクを避ける)
- 材質・柄・形状で迷ったら別扱い

## 禁止事項

- 入力ファイル (仮クラスタ情報、画像 webp) を書き換えない
- 指定出力パス以外に書き出さない
- rowIndex を改変しない (プロンプト内の値をそのままコピー)
- subgroup に含めない rowIndex を残さない (必ず全件を subgroup に割り当てる)

## 1 件のみのグループについて

仮クラスタが 1 件のみの場合、本プロンプトは起動されない (Node 側で単独確定として処理済み)。本プロンプトに来るのは必ず 2 件以上のグループ。

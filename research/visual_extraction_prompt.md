# 第 5 段階 substep 5-3 (視覚属性抽出) プロンプト

## 【絶対禁則】ファイル操作の制約

以下を厳守。違反は仕様違反として扱う。

1. **指定出力パス以外にファイルを作成しない**
   - 出力パスは Agent 起動時に指示される (プロンプト末尾の「## 指定出力パス」セクション参照)
   - 中間ファイル・デバッグファイルを勝手に作らない
2. **入力ファイルを書き換えない**
   - バッチ JSON、画像 webp はすべて読み取り専用として扱う
3. **プロジェクト内の他ファイルを変更しない**
   - Edit / Write / NotebookEdit は、指定出力パスへの 1 回の書き込みのみに使う
   - 他の変更が必要になった場合は実行せず、プロンプト発行者に報告する
4. **違反しそうな操作は実行せず報告する**

## タスク

各商品の **画像 + タイトル + 既存属性** を見て、category / subcategory / color / pattern / material を補正・補完する。size / quantity は触らない (タイトル由来の値をそのままコピー)。

入力はバッチ JSON ファイル 1 つ (最大 50 件)。出力は全件分の attributes を入れた JSON を指定パスに 1 回で書き出す。

## 入力フォーマット

プロンプト末尾の「## バッチファイルパス」セクションに絶対パスが示される。そのファイルを Read すると以下の構造:

```json
{
  "batchNum": 0,
  "items": [
    {
      "rowIndex": 163,
      "id": "m...",
      "name": "タイトル文字列",
      "imagePath": "/abs/path/163.webp",
      "currentAttributes": {
        "category": "ショーツ",
        "subcategory": "キッズショーツ",
        "color": ["ブラック"],
        "size": "100cm",
        "quantity": "4枚"
      }
    }
  ]
}
```

## 作業手順 (**バッチ内 1 件ずつ逐次処理、全件揃ってから 1 回で Write**)

1. バッチ JSON を Read
2. items の各行について以下をメモリ上で処理:
   - `imagePath` を Read ツールで開いて画像を取得
   - タイトル + 現在属性 + 画像から、後述のルールに従って 5 フィールド + 2 新設フィールドを判定
   - 結果オブジェクトをメモリに保持
3. **全 50 件 (またはバッチ件数分) 処理が完了したら** 指定出力パスに JSON 配列として 1 回で書き込む
4. 書き込み後、Read して件数を自己検証

## 各フィールドの判定ルール

### category (粗いジャンル)

- プロンプト末尾の **vocab** リスト (category) から選ぶ
- `currentAttributes.category` が vocab にあり、画像と矛盾しなければそのまま採用
- 明らかに画像と合わない場合のみ修正
- vocab に該当がなく新規の粗ジャンルが必要な場合は追加 (ただし既存と似た粒度で)
- `null` は不可 (必ず何か入れる。どうしても不明なら `"その他"`)

### subcategory (細かいジャンル)

- category に用途・機能修飾を足した名前 (例: ハーフパンツ / ビーチタオル / ハンドクリーム)
- vocab (subcategory) から選ぶ。新規追加も可
- 該当する修飾が無ければ `null` のまま

### color (色、配列)

- 画像を見て判定。複数色あれば配列に複数要素 (例: `["ベージュ", "ブラック"]`)
- メタルールを適用:
  1. 漢字色名 (1〜2 文字) → カタカナ (黒→ブラック / 白→ホワイト / 灰→グレー 等)
  2. 英語色名 → カタカナ (BLACK→ブラック 等)
  3. 「○色」接尾辞は除去 (黒色→ブラック)
  4. 「○色」(○ 単漢字) パターン → 一般カタカナ色 (水色→ライトブルー 等)
- 透明・白基調などで色を 1 つに絞れないときは主要な 1 色
- 色の属性が無い商品 (モノクロ写真印刷物、色判別不能等) は `null`

### pattern (柄) **【新設、必ず判定する】**

- 画像の柄・プリントデザインを単語で表現
- 代表例: `無地` / `花柄` / `チェック` / `ストライプ` / `ボーダー` / `水玉` / `動物柄` / `キャラクター柄` / `ロゴ柄` / `幾何学柄` / `和柄`
- 柄が無い = `無地`
- 画像が不鮮明で判定不能な場合は `null`

### material (素材) **【新設、判定困難なら null】**

- 画像の質感から判定
- 代表例: `綿` / `ポリエステル` / `本革` / `合皮` / `ビニール` / `OPP` / `金属` / `木` / `プラスチック` / `シリコン` / `ガラス` / `紙`
- 質感判定が困難なものは `null` で構わない (無理に埋めない)

### size / quantity (**触らない**)

- `currentAttributes.size` と `currentAttributes.quantity` をそのままコピー
- 画像から新たに判定してはいけない (`M/L/XL`、`100 枚` 等は画像では判別不可能)

## 出力フォーマット

入力の items と同じ順番、同じ件数で配列を書き出す:

```json
[
  {
    "rowIndex": 163,
    "id": "m...",
    "name": "タイトル",
    "attributes": {
      "category": "ショーツ",
      "subcategory": "キッズショーツ",
      "color": ["ブラック"],
      "size": "100cm",
      "quantity": "4枚",
      "pattern": "無地",
      "material": "綿"
    },
    "notes": "修正したフィールドがあれば簡潔に記載"
  }
]
```

- `notes` は修正箇所を短く書く (例: `"category を リボン から ショーツ に修正、画像がキッズショーツ"`)。修正なしなら空文字 `""`
- 入力と出力は rowIndex 基準で 1:1 対応、件数も一致

## 確信できないときの扱い

- `pattern` と `material` は **`null` が多発しても構わない**。「判定できない」が正しい答え
- `currentAttributes` が画像と矛盾しなければ無理に修正しない
- 画像が不鮮明・荒いときは `null` に逃げる (曖昧な判定を返さない)

## ブランド・キャラクターの扱い

- ブランド名・キャラクター名は前段で既に除外済 (第 4 段階)
- 画像判定でブランド・キャラ要素を新たに見つけても、本段階では無視する (除外判定は行わない、属性付与だけに集中)

## 禁止事項

- バッチ内の全件を処理する前に Write しない (中途半端な書き出し禁止)
- 1 件ずつ個別ファイルに書かない (指定出力パスに 1 回だけ書く)
- 想定出力フォーマット以外のキーを追加しない
- 入力ファイル (batch_NNN.json、画像 webp) を書き換えない

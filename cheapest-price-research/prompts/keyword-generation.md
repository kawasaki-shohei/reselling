## タスク

中国輸入物販で販売中の商品について、メルカリで **現在販売中の同一商品** の中から最安値を見つけるリサーチを行う。その第 2 段階として、各商品ごとに「メルカリ検索に投げるキーワード」を生成する。

## 重要: CSV 商品名は参照しない (URL ベース運用)

入力 CSV (`source.csv`) の **`商品名` 列は信頼できない場合がある**:

- 物販オーナーの「出品予定の意図メモ」であり、URL が指す実物商品と食い違うことがある
- 例: 過去 run で「宅配ビニール袋 B4 100枚 白」と CSV に書かれていたが、URL の実物は黒 (description に「カラー: ブラック」と明記)
- そのまま信じてキーワードに反映すると、本来の対象商品 (黒) と検索結果 (白) が食い違い、最安値リサーチが空振りする

そこで本タスクでは:

- **URL の実物データ (target_detail JSON + photos[0] 画像) を正とする**
- CSV 商品名は **参照しない** (商品番号 / URL 一覧の取得用にのみ source.csv を使う)
- 画像で判明した色 (タイトルに書かれていなくても) を**必ずキーワードに含める**

## 同一商品判定の前提 (必読)

メルカリの中国輸入品は、出品者が他出品者通報リスクを避けるためタイトル・画像・説明文を意図的に変えて出品する慣習がある。よって「タイトル文字列の一致」ではなく **実体属性 (色・サイズ・個数・セット数・柄・素材・用途) の一致** で同一商品を判定する。

詳細は以下のドキュメントを **必ず Read してから** キーワード生成に入ること:

## 同一商品判定の軸 (キーワードに含めるべき要素)

以下が違えば別商品扱いになる軸。画像・タイトル・説明文を統合してこれらの値を判定し、キーワードに反映する。

| 軸 | 取得元 | 例 |
|---|---|---|
| 色 | **画像で判定**、タイトル / 説明文で補完 | 黒 / 白 / ブラウン / ベージュ / シルバー / ゴールド 等 |
| サイズ | タイトル / 説明文 (画像内に書かれていれば画像も) | S / M / L / XL、A3 / A4 / B4、80×120、25cm 等 |
| 個数・セット数・容量 | タイトル / 説明文 (画像内に書かれていれば画像も) | 2個セット / 5枚セット / 100枚 / 500g 等 |
| 柄 | **画像で判定**、タイトル / 説明文で補完 | 無地 / 花柄 / チェック / 迷彩 / キルティング 等 |
| 素材 | 説明文、画像での質感 | 本革 / 合皮 / ナイロン / ポリエステル 等 |
| 用途・機能 | タイトル / 説明文 / 画像 | ショルダーバッグ / トートバッグ / ロングリード (訓練用) / 自動巻き取り式 等 |

## 入力

### 対象商品コード一覧

呼び出し側が処理対象の商品コード一覧を inline で指定する (デフォルト 20 件、最大 50 件目安)。本プロンプトでは source.csv を Read しない (呼び出し側が必要な情報を inline で渡す前提)。

### 各商品の入力ファイル

- **対象詳細 JSON**: `{TARGET_DETAIL_DIR_ABS_PATH}/{商品番号}.json` を Read
  - 構造: `{ id, name, price, description, photos (URL 配列), seller, item_condition, ... }`
  - 特に `name` (タイトル) と `description` (商品説明文全文) を参照
- **対象画像**: `{TARGET_IMAGES_DIR_ABS_PATH}/{商品番号}/photo_1.jpg` を Read で画像認識
  - 色 (黒 / 白 / ベージュ等) と柄 (キルティング / 無地等) を必ず判定

### (枝番時のみ) CSV 商品名ヒント

1 つのメルカリ URL を複数の商品番号が共有する場合 (枝番)、呼び出し側が枝番商品の「本人 CSV 商品名 + 兄弟コードの CSV 商品名」を inline で渡す。詳細は「## 枝番処理 (同 URL 共有時のみ)」セクション参照。

## 出力

`{OUTPUT_CSV_ABS_PATH}` に 4 列 CSV (UTF-8 BOM **なし**):

```
商品番号,対象タイトル,メルカリURL,検索キーワード
FD00101,スタッズベルト ...,https://jp.mercari.com/item/m92167660103,スタッズベルト V 黒
```

- 2 列目「対象タイトル」は **CSV 入力の商品名ではなく、target_detail JSON の `name` フィールドの値** を入れる
- 3 列目 URL は CSV 入力の URL をそのまま
- 4 列目「検索キーワード」が本タスクの生成物

## キーワード生成ルール

1. **2〜3 語をスペース区切り** (半角スペース) で生成する
2. **商品が特定できる中核名 (カテゴリ・用途) + 同一商品判定の軸 (色・サイズ・個数等)** を含める
3. **色は画像で判定し、タイトルに無くても必ず入れる** (タイトルが色を省略していても、画像で黒なら「黒」を入れる)
4. **修飾語の羅列は避ける** (人気・おしゃれ・上品・韓国・男女兼用・春夏・新品 等は基本入れない)
5. **対象タイトルが極端に短い場合** (1 語のみ) は、そのキーワード + 画像から判明した属性を組み合わせる

## 例

| 対象タイトル (target_detail.name) | 画像 | description 抜粋 | 検索キーワード |
|---|---|---|---|
| `宅配ビニール袋 B4 100枚 新品 テープ付 宅急便 ネコポス ゆうパケット` | **黒い** ビニール袋の束 | 「カラー: ブラック」明記 | `宅配ビニール袋 B4 100枚 黒` ← **タイトルに色なし、画像で黒判明 → キーワードに「黒」必須** |
| `犬 ロングリード 10m 訓練用 トレーニング 大型犬 中型犬 黒` | 黒 | ナイロン製、ロングリード | `ロングリード 10m 黒` |
| `2個セット スタッズベルト スタッツ メンズ レディース Y2K パンク ロック V 黒` | 黒、V字スタッズ | 個数差 | `スタッズベルト 2個セット V 黒` |
| `ハンドバッグ 大容量 黒 韓国 キルティング マザーズバック トートバッグ A4` | 黒、菱形キルティング | ナイロン | `トートバッグ キルティング A4 黒` |
| `撮影用 背景布 白 ホワイト 1.5×2メートル 無地 目隠し スクリーン 投影` | 白、無地 | 1.5×2m | `背景布 白 1.5×2m` |

## 枝番処理 (同 URL 共有時のみ)

通常 (URL が単独のコード): CSV 商品名は信頼しない、画像 + target_detail のみで判定する。

**例外**: 1 つのメルカリ URL を複数の商品番号が共有する場合 (枝番)、その差分情報は CSV 商品名にしか書かれていないので、CSV 商品名の差分を**軸別判定ルール**に従ってキーワードに反映する。呼び出し側が枝番ヒント (本人 CSV 商品名 + 兄弟コードの CSV 商品名) を inline で渡す。

### 軸別判定ルール

| 差分の軸 | 判定 |
|---|---|
| 個数 / セット数 / 枚数 (例: 「2個」「3点セット」「100枚」) | **採用** (URL 実物には書かれない出品意図情報) |
| サイズ表記 (例: 「16cm」「Lサイズ」「38mm」「XL」) | **兄弟間で明示的に異なるサイズを指定していれば採用** (URL 実物が単一サイズでも CSV 指定優先。物販オーナーは別サイズで仕入れる意図) |
| 色 (例: 「ピンク」「グレー」「透明」) | **兄弟間で明示的に異なる色を指定していれば採用** (URL 実物に該当色が無くても CSV 指定優先。物販オーナーは別色で仕入れる意図)。一部のみ色指定で他は色言及なしの場合は、全員 URL 実物の色とみなす |
| 機能補足 (例: 「テープ付」「新品」「送料無料」) や曖昧表現 | **不採用** (差分軸として弱い) |

### 軸採用の核となる考え方

枝番は物販オーナーが「同じ URL 商品ページを参考にしつつ、**実際には別仕様 (別サイズ・別色・別個数) で仕入れて売る**」意図のメモ。よって**兄弟間で明示的に差分がある軸 (個数・サイズ・色) は CSV 指定を優先し、URL 実物の単一仕様に縛られない**。検索キーワードに CSV 指定値を入れることで、メルカリ上のその仕様の最安値を引く。

### 例

- FD00201 (CSV: アヌビス) / FD00202 (CSV: 2個 アヌビス) → 差分=個数 → "アヌビス 真鍮 1個" / "アヌビス 真鍮 2個"
- FD07601 (16上履き) / FD07602 (17上履き) / FD07603 (18上履き) → 差分=サイズ (兄弟間で明示的に異なる) → URL 実物が 14cm のみでも CSV 指定優先 → "上履き 白 16cm" / "17cm" / "18cm"
- FD07401 (グレー 衣装ケース 3枚) / FD07402 (ピンク 衣装ケース 3枚) → 差分=色 (兄弟間で明示的に異なる) → URL 実物がグレーのみでも CSV 指定優先 → "衣装ケース 3枚 グレー" / "衣装ケース 3枚 ピンク"
- FD02701 (B4 100枚 白) / FD02702 (B4 100枚 テープ付) → 一方は「白」、他方は色言及なし → 兄弟間で**色が明示的に異なるとは言えない** → 両者 URL 実物の黒で統一 → `宅配ビニール袋 B4 100枚 黒`

## バッチ逐次保存 (中断耐性の要)

商品ごとに以下を繰り返し、**1 商品の判定が終わるごとに即 OUTPUT_CSV に追記** すること。まとめて一括書き出しは禁止 (中断で判定がロストする、親 Claude は書き出されたファイルしか見ない)。

1. 出力 CSV `{OUTPUT_CSV_ABS_PATH}` にヘッダ行 `商品番号,対象タイトル,メルカリURL,検索キーワード` を書き出す
2. 呼び出し側から渡された商品コード一覧を順に処理:
   - `{TARGET_DETAIL_DIR_ABS_PATH}/{商品番号}.json` を Read → `id`, `name`, `description` を取得
   - `{TARGET_IMAGES_DIR_ABS_PATH}/{商品番号}/photo_1.jpg` を Read で画像認識
   - 枝番ヒントが渡されていれば「## 枝番処理」に従い差分も考慮
   - キーワード判定
   - 出力 CSV に 1 行追記
3. 全商品完了したら完了報告

## 完了報告

出力 CSV を書き終えたら、以下を報告する:

- 出力 CSV の行数 (ヘッダ含む)
- 入力 source.csv の商品数 (ヘッダ除く)
- 行数が一致しているか
- target_detail / target_images の Read エラーが発生した商品があれば一覧
- スポットチェック用に 5〜10 件抜粋して「対象タイトル + 画像で判定した色 → キーワード」のマッピングを示す
- 「タイトルに色記述なし → 画像から色を抽出してキーワードに反映した」ケースが何件あったかも報告 (重要)

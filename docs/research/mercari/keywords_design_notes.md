# keywords.json の設計メモ (除外辞書の運用原則)

`procedures/exclude_by_keywords/keywords.json` を運用・拡張する際に踏まえる **設計原則・注意パターン** を記述する。

## このファイルの立ち位置

- 個別キーワードの「これは除外する/しない」は本ファイルでは扱わない。**keywords.json 本体** または **新規追加フロー** (`procedures/mercari-research-v2.md` 第 3 段階 `dictionary_expansion_step`) で扱う
- 本ファイルが扱うのは「どういう設計で keywords.json を組み立てるか」のパターン・原則
- Opus による新規キーワード抽出 (`dictionary_expansion_step`) の参照文書としても使う

## 辞書の構成

`keywords.json` は `priority` (カテゴリ優先順) と `keywords` (カテゴリごとのキーワード配列) からなる。各キーワードは以下のいずれかの形式:

| 形式 | マッチ条件 |
|---|---|
| 単純文字列 | タイトルに**含まれていれば**マッチ |
| notWith オブジェクト | タイトルに含まれていて、かつ notWith の語が**含まれていなければ**マッチ |
| withAll オブジェクト (要拡張) | タイトルに含まれていて、かつ withAll の語も**含まれていれば**マッチ |

---

## パターン 1: 短語・一般語の誤爆対策

短語 (2〜4 文字) や日本語一般語は `includes()` 部分文字列マッチで誤爆しやすい。対処は 2 通り。

### 1a. 単独で残して `notWith` で防ぐ

単独キーワードとしての除外効果が大きく、特定の誤爆語だけ避けたいとき。

| キーワード | 誤爆する語 | 現行 notWith |
|---|---|---|
| ガム | ギンガム (柄) | `["ギンガム"]` |
| 洗顔 | 洗顔パフ/タオル/ブラシ/ネット (道具) | `["洗顔パフ", "洗顔タオル", "洗顔ブラシ", "洗顔ネット"]` |
| シュガ (K-POP) | ラッシュガード (水着) | `["ラッシュガード"]` |
| キャンディ | キャンディイエロー/ボンボン/柄 (色名等) | `["キャンディイエロー", "キャンディボンボン", "キャンディ柄"]` |
| ハンドメイド | 生地/ファスナー/レジン等 (ハンドメイド用素材) | 12 語 (生地・布地・ファスナー・シリコンモールド・レジン・ビーズ・コットン・リボン・レース 等) |

```json
{ "keyword": "ガム", "notWith": ["ギンガム"] }
```

### 1b. 単独を諦めて具体語に置き換える

単独の除外効果が小さい、または誤爆語が多すぎて notWith が膨らむ場合。**キーワード自体を削除し、より特定性の高い表記に置き換える**。

| 旧キーワード | 置き換え | 理由 |
|---|---|---|
| アイス | `アイスクリーム` | 食品アイスは複合語で拾える、単独は手芸材料 (アイスヤーン) で誤爆 |
| RM (K-POP) | `P1HARMONY` 系 | FARM/WARM/ARMS で誤爆多数、BTS は `BTS` 単独で拾える |
| ウタ | `UTAA` | 「うた (歌)」混同防止 |
| ベア | 削除 | 代替が不要な文脈 |
| リーボック | `REEBOK` | カタカナ版は単独では無理、英字正規表記に集約 |
| ニトリ | 追加しない | ニトリル手袋と誤爆、家具ブランドのニトリは実データに出現しない |
| トナー | `トーニングトナー` | 化粧品トナー単独では誤爆広範 |
| ポロ / POLO | `Ralph Lauren` / `ビバリーヒルズポロクラブ` / `WESTERN POLO` | jacadi 子供ポロシャツ等を誤除外する |

### 1a と 1b の使い分け

- **デフォルトは 1b**: notWith を重ねるのはモグラ叩き。具体語への置き換えが本質的
- **1a が適するケース**: 除外効果が大きい (多数のタイトルをカバー) かつ誤爆語が限定的で収束している
- 迷ったら 1b (保守コストが低い)

## パターン 2: 組み合わせ判定と `withAll`

### 問題

単独ではブランド名や禁止商品と結びつかないが、他の語との組み合わせで模造品・禁止商品と判定できるケース。

| 組み合わせ | 想定する除外対象 |
|---|---|
| `クロム + クロス` | クロムハーツ (十字架モチーフ) |
| `クロム + 十字架` | 同上 |
| `シリコンモールド + クロス` | クロムハーツの十字架型ネイル型 |
| `喜平 + ウォレットチェーン` | クロムハーツ類似 (アパレル PDF #9) |

単独の `クロム` は一般用語 (クロムネイル / クロムパウダー / クロムパーツ = 金属光沢ネイル技法) なので除外できない。

### 対処

**withAll** で「複数の語が同時にあれば除外」パターンを書く:

```json
{ "keyword": "クロム", "withAll": ["クロス"] }
{ "keyword": "クロム", "withAll": ["十字架"] }
{ "keyword": "シリコンモールド", "withAll": ["クロス"] }
```

(`exclude_by_keywords.js` に withAll の処理実装が必要。現状は未実装)

### 判断指針

- 「単独では誤爆するが、特定語と組み合わせれば確度の高い模造品判定になる」パターンは withAll で表現する
- 複数のトリガー語がある場合は、行ごとに展開する (各行は AND 条件、行同士は OR)

## パターン 3: `notWith` と `withAll` の使い分け

| シナリオ | 使うもの |
|---|---|
| **単独で基本除外、一部の文脈でのみ誤爆** | notWith (パターン 1a) |
| **単独では除外不適、特定の語との組み合わせでだけ除外** | withAll (パターン 2) |
| **単独では除外不適、具体語への置き換えで解決できる** | notWith/withAll ではなくキーワード自体を置き換える (パターン 1b) |

---

## カテゴリ優先順 (primary 決定ルール)

複数カテゴリに同時にマッチしたとき、`priority` 配列順で primary が決まる:

```
food > plant_quarantine > medical > cosmetics_yakki > character_copyright > brand_imitation > electronics_check > handmade > private_transaction
```

法令リスクが大きいものほど前に並ぶ (食品衛生法・植物検疫 > 薬機法 > 版権 > 模造 > 電波法 > ハンドメイド > 取引専用)。`private_transaction` は法令違反ではないが、仕入れ判断不能・運用トラブルリスクの観点で除外。

---

## メンテナンスルール

- 新規キーワード追加時は **最新のリサーチデータで検索**し、誤爆がないか必ず確認する
- 誤爆があれば対処の優先順位:
  1. **具体名・複合語への置き換え** (パターン 1b) を第一候補にする
  2. それが無理なら `notWith` を追加 (パターン 1a)
  3. 組み合わせ判定が必要なら `withAll` を追加 (パターン 2)
- **Opus による新規キーワード抽出** (`dictionary_expansion_step`) でも、本ファイルのパターンを参照して候補を出させる
- 変更理由 (なぜ追加/削除したか) は **Git コミットメッセージ** に残す
- 大きな設計判断 (フォーマット拡張、カテゴリ追加等) は `adr/` に ADR として記録する

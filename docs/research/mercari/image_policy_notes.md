# メルカリの画像利用ルールと実態

本文書は同一商品判定パイプライン (手順書 [`procedures/mercari-research-v2.md`](../../../procedures/mercari-research-v2.md) 第 6 段階) の設計を検討する際に必要となる前提情報を整理する。

## 背景

中国輸入物販のリサーチで、同一商品クラスタを機械的に束ねる手法 (画像ハッシュ / 画像エンベディング) を検討する過程で、「複数 seller が同じ商品画像をどの程度共有しているか」を把握する必要があった。

2026-04-25 に Web 検索で事実確認した結果を記録する。

## メルカリ公式ルール

メルカリヘルプ「[他会員が撮影した画像や、メルカリ外にある画像/文章などを無断で使用すること](https://help.jp.mercari.com/guide/articles/872/)」は **禁止行為** として明記されている。対象は:

- 他会員 (出品者) が撮影した画像を無断使用する
- メルカリ外のサイト (通販サイト、他フリマ、メーカー公式など) の画像を無断使用する

自分で撮影した画像を再出品で使うことは禁止されていない。

## 違反時のペナルティ

メルカリヘルプ「[禁止されている行為](https://help.jp.mercari.com/guide/articles/258/)」より:

- 取引キャンセル
- 商品削除
- 事務局から警告
- 一定期間または無期限の利用制限
- 悪質な場合はアカウント停止 (強制退会)

検知の厳密さについては公式情報で定量化されていない。通報ベースや自動検知で発見される事例がユーザー体験談として複数報告されている (参考: [ウチブログ](https://kries.jp/uchiblog/mercari-unauthorizedcopying))。

## 現場の実態 (3 パターン混在)

中国輸入物販の seller が用いる画像の出所は、実態として以下 3 パターンが混在する:

| パターン | 出所 | 検知リスク | 実務での観察 |
|---|---|---|---|
| (a) 仕入れ元 (アリババ等) の画像を無加工で使い回し | 仕入れ先サイト | 高 (ルール違反状態) | 実際には検知を免れている事例が多い。複数 seller が同じ画像を使う状況が発生 |
| (b) 軽加工で検知回避 | 仕入れ元画像 + 明るさ・色調・クロップ等の加工 | 中 | 無加工使い回しよりは目立たない |
| (c) 自分で撮影 | seller 自身 | なし | ルール上安全。真面目な seller に多い |

既存 run の Sonnet 画像判定で「画像完全同一」と判定されるケースは (a) のパターン。一方 (c) の seller は完全に別画像になり、ピクセル単位や画像ハッシュでは同一判定できない。

## 同一商品判定パイプラインへの含意

本リポジトリの手順書 第 6 段階の同一商品判定は、上記 3 パターンを前提に設計する必要がある。

### 手法ごとの得意・不得意

| 手法 | (a) 無加工使い回し | (b) 軽加工 | (c) 自己撮影 |
|---|---|---|---|
| 画像 perceptual hash (pHash) | ◎ 取れる | △ 距離が中程度、閾値調整次第 | ✗ 取れない |
| 画像エンベディング (CLIP 等、意味理解ベース) | ◎ 取れる | ◎ 取れる | ◯ 意味的に同じ商品と認識できれば取れる |
| タイトル類似度 (n-gram Jaccard) | 参考値として組み合わせ可 | 同左 | 同左 |
| 現行 6 軸完全一致 (Sonnet 属性抽出後) | 属性抽出が揃えば取れる | 属性抽出のブレ次第 | 属性抽出のブレ次第 |

### 実装方針の判断材料

- (a) だけに絞れば軽量な pHash で十分だが、実運用では (b)(c) も一定比率存在する
- (c) の比率が高ければ、画像エンベディングの導入が本質的に必要になる
- **実装着手前に、既存 run のデータで (a)(b)(c) の比率を pHash 距離分布から測る** のが、手法選択の根拠になる
